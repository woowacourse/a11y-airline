# ✈️ 누구나 접근할 수 있는 항공사 웹사이트

항공사 웹사이트 컴포넌트의 스크린 리더 접근성 높이기

## 실행과 검증

```sh
npm ci
npm run dev
npm run build
npm run lint
```

개발 서버를 실행한 뒤 [브라우저 동작 검증 페이지](http://localhost:5173/a11y-airline/tests/accessibility.html)를 열면 검증 결과가 표시됩니다. 별도 테스트 라이브러리 없이 실제 브라우저에서 모달의 진입 포커스·배경 탐색 차단·닫기·포커스 복귀, 문서 구조, 캐로셀의 상품별 정보와 링크, 양방향 순환, 전환 후 포커스 유지, 승객 수 제한, 도움말, 메뉴의 펼침 상태를 확인합니다.

## 반영한 접근성 개선

- 페이지 제목과 `header`, `nav`, `main`, `section`, `footer`로 문서 구조를 제공합니다. 헤딩은 `h1 → h2` 순서입니다.
- 첫 번째 링크인 '본문으로 바로가기'는 포커스 시 나타나며, 메뉴를 건너뛰고 본문으로 포커스를 이동합니다.
- 캐로셀은 현재 상품만 링크로 제공합니다. 링크 이름에 전체 개수, 현재 순서, 노선, 좌석, 가격과 새 창 안내를 담았습니다.
- 이전/다음 버튼에 이름을 제공하고, `aria-live="polite"`, `aria-atomic="true"`로 전환한 상품을 안내합니다. 전환 시 버튼의 포커스는 유지합니다.
- 장식용 이미지는 빈 대체 텍스트로 중복 낭독을 피합니다.
- 모바일 메뉴는 펼침 상태와 제어 대상을 전달합니다. 하위 메뉴는 기본 `details`/`summary`로 키보드와 터치에서 열 수 있습니다.
- 승객 수는 `output`으로 안내하고, 인원 제한 안내 영역을 처음부터 유지합니다. 도움말은 키보드 포커스와 클릭으로 열고 Escape로 닫을 수 있습니다.
- 홍보 팝업은 페이지 진입 시 `dialog.showModal()`로 엽니다. 제목·설명을 연결하고 닫기 버튼에 포커스합니다. Tab·Shift+Tab은 두 버튼 사이에서 순환합니다. 열린 동안 배경은 탐색·조작할 수 없으며, Escape·닫기 버튼·팝업 바깥 클릭으로 닫으면 본문으로 포커스를 이동합니다. [W3C의 기본 dialog 접근성 안내](https://www.w3.org/WAI/WCAG22/Techniques/html/H102)를 참고했습니다.

## 직접 확인할 항목

자동 검증은 실제 스크린 리더의 음성 출력을 보장하지 않습니다. 모바일 VoiceOver 또는 TalkBack에서 다음 항목을 확인하고, 제출할 PR에는 개선 전후 영상을 첨부해 주세요.

- [ ] 페이지에 진입하면 팝업의 제목·설명과 닫기 버튼을 인지할 수 있는가?
- [ ] 팝업이 열려 있는 동안 Tab·Shift+Tab과 스크린 리더로 배경을 탐색할 수 없는가?
- [ ] Escape·닫기 버튼으로 팝업을 닫으면 본문으로 포커스가 이동하는가?
- [ ] 팝업을 닫은 뒤 본문 바로가기로 메뉴를 건너뛸 수 있는가?
- [ ] 헤딩과 주요 영역을 통해 페이지를 탐색할 수 있는가?
- [ ] 상품 하나를 선택했을 때 전체 개수·순서·노선·좌석·가격이 한 번에 전달되는가?
- [ ] 이전/다음 버튼으로 이동하면 새 상품 정보를 안내하고, 현재 버튼에서 계속 조작할 수 있는가?
- [ ] 각 상품 링크가 올바른 상품을 새 창으로 여는가?
- [ ] 메뉴, 승객 수, 도움말을 화면을 보지 않고도 사용할 수 있는가?

예제의 '앱에서 열기' 버튼은 실제 앱 URL이 제공되지 않아 연결하지 않았습니다. GitHub Pages 배포와 PR 제출은 별도로 진행합니다.
