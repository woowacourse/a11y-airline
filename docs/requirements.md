## 미션 소개

여러 서비스에서 자주 쓰이는 **이미지 캐로셀 컴포넌트**의 접근성을 개선한다. 항공사 웹사이트의 컴포넌트라고 가정하고, 최종적으로는 **항공사 웹사이트 모바일 페이지 1개**의 접근성을 개선한다.

- 저장소를 fork한 뒤 `package.json`의 `"homepage"`에 들어 있는 `{username}`을 본인 아이디로 바꾸고, `npm run deploy`로 GitHub Pages에 배포해 확인한다.

## 학습 목표: 최소한의 마크업으로 최대한의 접근성 확보하기

- 시맨틱 태그로 웹 페이지 구조를 명확히 하고 의미를 직관적으로 전달한다.
- 마크업을 최소한으로 쓰고 불필요한 요소를 줄이며, HTML 기본 기능을 최대한 활용한다.
- ARIA 속성은 꼭 필요할 때만 써서 추가 정보를 제공한다. (**No ARIA is better than Bad ARIA**)
- 시각적 표현과 접근성을 모두 만족시키는 방법을 함께 고민한다.

## 필수 요구사항

### 1) 컴포넌트 접근성 개선: 이미지 캐로셀

항공사 메인 화면의 "프로모션 진행 중인 노선·가격 정보" 섹션을 스크린 리더가 읽을 수 있게 개선한다.

- [ ] 스크린 리더가 캐로셀의 **전체 아이템 수**를 읽을 수 있어야 한다.
- [ ] 스크린 리더가 캐로셀 안의 **각 아이템 정보**를 읽을 수 있어야 한다.
  - [ ] 여행지, 좌석 유형, 가격 정보를 **한 번에** 읽을 수 있어야 한다.
  - [ ] 이전/다음 아이템으로 이동하고, **현재 보이는 아이템의 정보**를 읽을 수 있어야 한다.
- [ ] 각 아이템을 선택하면 **아이템별 링크로 이동**할 수 있어야 한다.

**Before (현재 문제)**

- 이전/다음 버튼에 이름이 없어서 "버튼"이나 이미지 파일 이름으로만 읽힌다.
- 출발·도착, 좌석 유형, 가격이 따로따로 읽혀서, 상품 하나의 정보를 들으려면 여러 번 넘겨야 한다.
- 전체 상품 수와 지금 몇 번째 상품을 보고 있는지 알 수 없다.
- 카드가 링크나 버튼이 아니라서, 선택하면 상품 페이지로 이동한다는 것을 알 수 없다.

**After (읽기 예시, 똑같지 않아도 되고 더 명확한 방식이 있으면 자율적으로 개선)**

```
프로모션 여행 상품
이전 여행 상품, 버튼
3개 중 1번째, 서울/인천에서 두바이, 일반석 왕복, 1,121,600원, 링크
다음 여행 상품, 버튼

(다음 여행 상품 버튼을 두 번 탭)
3개 중 2번째, 서울/인천에서 바르셀로나, 일반석 왕복, 1,515,200원
```

**참고: 지난 기수 PR (정답이 아니라 다양한 시도의 예시)**

- PR #177: before/after 영상
- PR #166: before/after 영상. 라이브 리전으로 "총 n개 중 k번째"를 안내
- PR #174: after 영상. 카드를 링크(`a`)와 `article`로 구성

### 2) 페이지 접근성 개선

사전 미션과 본 미션에서 구현한 내용을 합쳐 하나의 페이지로 구성하고, 페이지의 접근성을 점검·개선한다.

- [ ] 페이지를 **하나의 문서**로 읽을 수 있어야 한다.
  - [ ] 페이지에 적절한 **제목(`title`)**을 제공한다. 제목은 페이지의 주요 내용을 간결하게 설명해야 한다.
  - [ ] 페이지의 주요 영역을 **시맨틱 태그**로 명확히 구분한다.
  - [ ] **헤딩을 논리적인 순서**로 사용해 페이지 구조를 명확히 한다.
- [ ] 키보드 사용자를 위해 페이지 최상단에 **'본문으로 바로가기' 링크(skip link)**를 제공해 반복되는 메뉴를 건너뛸 수 있게 한다. (참고: github.com)

## 선택 요구사항: 팝업 모달 포커스 트랩

새로 론칭한 항공사 앱을 홍보하는 팝업 모달을 띄운다.

- [ ] 스크린 리더로 진입했을 때도 **팝업이 떴다는 것을 인지**할 수 있어야 한다.
- [ ] 팝업이 열려 있는 동안에는 **포커스가 팝업 안에서만** 이동해야 한다.
- [ ] 스크린 리더로 팝업을 **닫을 수 있어야** 한다.
- [ ] 키보드 접근성도 함께 고려한다. (키보드만으로 팝업에 바로 진입하고 닫을 수 있어야 한다.)

## 진행 방식

- 개인 미션이다.
- 예제 프로젝트를 fork해 개선한 뒤 PR을 보낸다.
- PR 템플릿(`.github/pull_request_template.md`)의 항목을 확인하고 채운다.
- 리뷰이가 제출한 PR을 리뷰한다.

## 리뷰이: PR에 넣을 내용

- PR 템플릿의 항목을 채운다.
  - 배포한 페이지 경로 (GitHub Pages)
  - 스크린 리더 화면 녹화 영상 (**before / after 필수**)
  - 요구사항별로 고민·학습한 내용과 개선 작업
- **우리 팀의 접근성 체크리스트 v1**
  1. 팀 서비스에서 가장 중요하고 자주 쓰이는 기능 플로우 1개를 골라 간단히 나열한다. (예: 로그인 → 상품 검색 → 상품 선택 → 장바구니 추가 → 결제)
  2. 각 단계마다 아래 질문을 생각해 본다.
     - 화면을 볼 수 없는 사용자가 이 단계를 완료할 수 있는가?
     - 이 단계에서 제공하는 정보나 지시 사항이 모든 사용자에게 명확한가?
  3. 팀원과 의견을 나눠 우선순위가 높은 체크리스트 항목을 만든다. (예: "모든 이미지와 인터랙티브 요소에 적절한 대체 텍스트가 제공되는가?")

## 리뷰어: 코드 리뷰 체크리스트

- 요구사항 항목을 기본적으로 잘 개선했는지 본다.
- 나와 다르게 시도한 방법이 있다면 서로 피드백한다.
  1. "최소한의 마크업으로 최대한의 접근성 확보하기" 의식적 연습
     - HTML 기본 기능을 최대한 활용하려 했는가?
     - 웹 표준을 준수하고 시맨틱 태그를 잘 활용했는가?
     - 적절한 ARIA 속성을 사용했는가?
     - 시각적인 사용성과 스크린 리더에서의 사용성을 함께 고려했는가?
  2. 접근성 체크리스트에 대한 피드백
     - 리뷰이가 주요 플로우에서 발견한 접근성 문제 중 우선 해결할 항목, 가장 큰 영향을 줄 개선, 사용자 경험에 가장 중요한 부분에 대해 의견을 나눈다.
