# 가치가챠 접근성 체크리스트 v1

## 가장 중요하고 자주 사용하는 기능 흐름

`가챠 검색 조건 선택 → 검색 결과 확인 → 가챠 선택 → 상세 정보 확인 → 3km 이내 판매점 확인`

사용자는 카테고리와 검색 결과에서 원하는 가챠를 선택합니다. 선택한 `gachaId`를 기준으로 가챠 상세 정보와 현재 위치에서 3km 안에 있는 판매점을 목록과 지도에서 확인합니다.

## 단계별 문제 정의

| 단계 | 화면을 보지 않고 완료할 수 있는가? | 정보와 지시 사항이 명확한가? | 우선 확인할 문제 |
| --- | --- | --- | --- |
| 검색 조건 선택 | 입력 요소에 연결된 이름이 있고 키보드로 조건을 선택할 수 있어야 한다. | 선택한 카테고리와 검색어, 검색 실행 방법이 텍스트로 전달되어야 한다. | placeholder나 아이콘에만 입력 목적을 의존하지 않는다. |
| 검색 결과 확인 | 스크린 리더가 결과 개수와 각 가챠 정보를 구분해서 읽을 수 있어야 한다. | 로딩 중, 결과 없음, 오류 상태가 시각적으로만 표시되지 않아야 한다. | 동적으로 바뀐 결과 개수와 상태를 적절히 안내한다. |
| 가챠 선택 | 각 결과를 실제 링크나 버튼으로 제공해 키보드로 선택할 수 있어야 한다. | 접근 가능한 이름만으로 어떤 가챠의 상세 페이지로 이동하는지 알 수 있어야 한다. | 클릭 가능한 `div` 대신 목적에 맞는 `a` 또는 `button`을 사용한다. |
| 상세 정보 확인 | 페이지 제목과 헤딩을 따라 이름, 가격, 카테고리 정보를 탐색할 수 있어야 한다. | 이미지에만 있는 정보는 대체 텍스트나 본문으로도 제공되어야 한다. | 장식 이미지는 빈 대체 텍스트를, 정보를 전달하는 이미지는 목적에 맞는 대체 텍스트를 제공한다. |
| 주변 판매점 확인 | 지도 마커를 사용할 수 없어도 같은 판매점을 목록에서 선택할 수 있어야 한다. | 매장명, 주소, 거리와 3km 검색 범위를 텍스트로 확인할 수 있어야 한다. | 지도만으로 결과를 제공하지 않고 동등한 판매점 목록을 함께 제공한다. |

## 우선순위 높은 체크리스트

- [ ] 페이지마다 내용을 설명하는 고유한 `title`과 하나의 `h1`이 있는가?
- [ ] `header`, `nav`, `main`, `section` 등으로 문서 구조와 탐색 순서가 드러나는가?
- [ ] 모든 입력 요소에 시각적으로 보이거나 프로그램으로 연결된 이름이 있는가?
- [ ] 클릭 가능한 요소를 목적에 맞는 `a` 또는 `button`으로 구현했는가?
- [ ] 검색 결과 카드의 이름, 가격, 카테고리가 하나의 항목으로 이해되는가?
- [ ] 로딩, 빈 결과, 오류, 검색 결과 개수처럼 동적으로 바뀌는 상태를 스크린 리더도 알 수 있는가?
- [ ] 키보드만으로 검색부터 상세 조회와 판매점 선택까지 완료할 수 있는가?
- [ ] 키보드 포커스의 현재 위치가 시각적으로 명확하고 논리적인 순서로 이동하는가?
- [ ] 이미지와 아이콘에 목적에 맞는 대체 텍스트가 있으며 장식 이미지는 중복해서 읽히지 않는가?
- [ ] 선택, 품절, 오류 상태를 색상이나 지도 마커 모양에만 의존하지 않는가?
- [ ] 지도에서 제공하는 판매점 정보를 동등한 텍스트 목록으로도 제공하는가?
- [ ] 위치 권한 거부나 위치 조회 실패 시 원인과 다음 행동을 텍스트로 안내하는가?
- [ ] 모바일 확대와 큰 글자에서도 주요 정보와 조작 요소가 가려지지 않는가?

## 수동 점검 방법

1. 마우스를 사용하지 않고 `Tab`, `Shift + Tab`, `Enter`, `Space`만으로 핵심 흐름을 완료한다.
2. 모바일 스크린 리더로 검색 조건, 결과 개수, 가챠 카드, 상세 정보, 판매점 목록을 순서대로 읽는다.
3. 지도를 조작하지 않고도 같은 판매점을 목록에서 찾고 선택할 수 있는지 확인한다.
4. 로딩, 검색 결과 없음, 위치 권한 거부, 서버 오류 상태를 각각 만들어 안내 문구를 확인한다.
