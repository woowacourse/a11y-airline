# 우리 팀의 접근성 체크리스트

## 핵심 플로우: 교환글 작성

`교환 목록 진입 → 글쓰기 버튼 선택 → 사진 첨부 → 보유 아이템·원하는 아이템 입력 → 등록 → 등록 결과 확인`

## 단계별 점검

| 단계 | 화면을 볼 수 없는 사용자가 완료할 수 있는가? | 정보와 지시가 모두에게 명확한가? |
| --- | --- | --- |
| 글쓰기 버튼 선택 | `+` 같은 아이콘만 있는 플로팅 버튼은 "버튼"으로만 읽혀 찾기 어려움 | 버튼 이름이 "교환글 작성"처럼 하는 일을 말해줘야 함 |
| 아이템 입력 | placeholder만 있고 label이 없으면 입력하는 순간 무엇을 쓰는 칸인지 사라짐 | 필수 항목 여부와 입력 형식이 미리 안내돼야 함 |
| 등록 | 오류가 있어도 빨간 테두리만 생기면 무엇이 잘못됐는지 모름 | 오류 메시지가 해당 입력칸과 연결되고 낭독돼야 함 |

## 우리 팀 접근성 체크리스트 v1

### 목록과 진입

- [ ] 아이콘만 있는 버튼(글쓰기, 사진 삭제 등)에 하는 일을 설명하는 이름이 있는가?

### 입력 폼

- [ ] 모든 입력칸에 `label`이 연결되어 있고, placeholder에만 의존하지 않는가?
- [ ] 필수 항목과 입력 형식을 입력 전에 안내하는가?
- [ ] 오류 메시지가 색상만이 아니라 텍스트로 제공되고, `aria-describedby`로 해당 칸과 연결되는가?
- [ ] 등록을 눌렀을 때 오류가 있으면 첫 번째 오류 칸으로 포커스가 이동하는가?

### 결과 안내

- [ ] 등록 후 포커스가 자연스러운 위치(작성한 글, 목록 맨 위 등)로 이동하는가?

## 리뷰어께 여쭤보고 싶은 점

- 사용자가 올린 아이템 사진은 대체 텍스트를 직접 입력받기 어렵습니다. 아이템 이름으로 대신하는 방식이 적절할지 궁금합니다.
- 등록 완료 후 포커스를 새로 작성한 글로 옮기는 것과 완료 메시지만 낭독하는 것 중 어떤 방식이 더 자연스러울까요?
